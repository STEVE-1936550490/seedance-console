# 已知问题

## 任务详情“已等待时间”显示异常

- 状态：`OPEN`，仅记录，当前不修复。
- 发现环境：公网 Console、真实 AICC 运行模式。
- 现象：任务详情中的“已等待时间”与用户实际等待时间不一致。当前尚未记录稳定的偏差
  数值或触发条件，因此不能将其归因于某一种时区、浏览器或任务状态。
- 当前实现位置：`apps/web/src/app/page.tsx` 的 `formatElapsed()`。它在非终态任务中使用
  浏览器 `Date.now()`，在终态任务中使用 `completedAt`，并解析 API 返回的 `createdAt`。
- 调查事项：记录问题任务 ID、页面显示值、客户端当前时间及 API 中带明确时区的
  `createdAt/completedAt`；检查客户端时钟偏差、时间戳格式、刷新/恢复任务后的状态以及
  跨时区和跨日场景。不得通过模糊字符串解析或服务器本地时区补偿来掩盖问题。
- 修复验收：QUEUED、SUBMITTING、PROCESSING 和各终态的计时均以同一真实时间点计算；
  页面持续刷新、浏览器刷新、从本地缓存恢复任务以及 UTC `Z`/明确偏移时间戳的结果
  一致；负数或非法时间戳需要明确处理并有测试覆盖。
- 安全边界：调查和测试使用 mock 或既有任务数据，不得为验证计时显示创建真实
  Provider 任务。

## 历史任务详情缺少完整提示词

- 状态：`TODO`，当前不修改前端。
- 数据现状：任务提示词已持久化在 PostgreSQL，任务列表与详情 API 均返回 `prompt`；
  这不是数据丢失问题。
- 现象：历史表格只提供受宽度和省略号限制的提示词摘要；点击“查看详情”后，创作页仅
  恢复任务结果，没有展示完整 `task.prompt`，也没有将它以只读方式恢复到详情区域。
- 后续实现：在历史任务详情中增加明确的“完整提示词”区域，保留原始换行和 Unicode，
  支持长文本换行与复制；不得把历史提示词误当作新任务表单内容而导致意外再次提交。
- 修复验收：列表摘要、详情全文、页面刷新、直接打开 `/?task=<taskId>` 和移动端布局均
  正常；无提示词时显示明确占位；HTML/脚本内容按 React 默认转义，不能引入 XSS。
- 安全边界：只使用数据库已有任务和 Mock 数据验证，不为 UI 验收创建真实 Provider
  任务。
