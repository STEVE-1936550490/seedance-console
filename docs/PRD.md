# Seedance Console MVP 产品需求

## 1. 背景与目标

Seedance Console 是部署在 Linux 服务器上的内部单用户 AI 视频生成控制台。它通过后端适配现有 Seedance 2.0 API，为使用者提供从输入提示词、上传参考图片到异步生成、查看结果的完整操作闭环。

产品可参考云平台视频生成模块的操作流程，但不得复用其品牌名称、文案、图标、截图、布局细节或其他视觉资产。本轮先用 Mock Provider 验证产品与工程闭环，真实接口必须等待 `docs/provider-api.md`。

## 2. 目标用户与核心流程

目标用户是可信内部网络中的视频创作人员或运维人员，不提供公开注册。

1. 用户进入创建页，填写文本提示词。
2. 用户可上传符合限制的参考图片。
3. 页面根据后端返回的 Provider 能力描述展示模型参数；当前仅展示 Mock Provider 已定义的测试参数。
4. 用户提交后，API 持久化任务并加入异步队列。
5. Worker 调用 Provider、轮询状态并保存进度、错误、用量和输出文件。
6. 用户在详情页轮询内部 API，预览或下载成功视频；失败时查看可操作的错误信息。
7. 用户可在历史页查看过往任务及其最终状态。

## 3. MVP 功能

### 3.1 创建与素材

- 创建文生视频任务，提示词为必填。
- 上传零张或多张参考图片；实际数量、格式和大小限制由配置及已确认的 Provider 能力决定。
- 提交模型参数，但只接受 Provider 适配器显式声明并校验的字段。
- 提交接口支持客户端请求 ID，避免重复创建。

### 3.2 异步任务

- 创建、排队、提交、处理中、成功、失败、取消、过期等内部状态。
- API 查询单个任务，前端采用有退避的轮询。
- 保存状态变更时间线、Provider 任务 ID（如有）和可展示的失败原因。
- Mock Provider 可确定性地模拟成功、失败和处理延迟。

### 3.3 历史与结果

- 按创建时间倒序分页展示任务历史，可按状态筛选。
- 成功任务支持浏览器视频预览与下载。
- 输出视频通过文件存储抽象保存，不直接暴露服务器任意路径。
- 记录 Provider 返回的用量；Provider 未返回时明确标记“不可用”，不得估算。

## 4. 非功能需求

- **安全**：Provider API Key 只存在于 API/Worker 环境；所有 Provider 请求由后端发起。上传需校验 MIME、扩展名、文件大小并净化文件名。
- **可靠性**：任务持久化、队列入队和 Worker 执行应支持幂等；服务重启后可恢复未完成任务；外部调用有超时和受控重试。
- **可观测性**：使用结构化日志和关联 ID；记录状态流转与耗时；Provider 请求/响应仅保存脱敏摘要。
- **性能**：HTTP 请求不等待视频生成完成；历史查询必须分页；文件下载支持流式响应。
- **可部署性**：通过 Docker Compose 在单台 Linux 服务器启动；持久化 PostgreSQL 数据和文件目录。
- **可维护性**：TypeScript strict；共享契约使用 Zod；Provider 与存储均通过接口替换。

## 5. 不包含的功能

- 真实 Seedance 2.0 接入（在接口文档确认前）。
- 充值、支付、计费结算、套餐或额度售卖。
- 公开注册、找回密码、组织、多租户和复杂权限系统。
- 移动端 App、模型市场、工作流编排、批量生成、视频编辑。
- 对 Provider 未返回的 token、费用、进度或参数进行推测。
- 高可用集群、跨地域容灾和大规模对象存储运维。

## 6. MVP 验收标准

- 一条 Mock 任务可从创建稳定流转至成功，结果可预览和下载。
- 可通过固定测试输入触发失败，并在界面看到脱敏且可理解的原因。
- 重启 API 或 Worker 后，已持久化任务不会丢失或重复提交。
- 浏览器网络请求和构建产物中均不含 Provider 密钥。
- 历史、状态、用量和状态事件与数据库记录一致。

## 7. 待确认

- `docs/provider-api.md` 中的认证、创建、查询、取消、输入素材传递、回调/轮询、幂等和用量协议。
- 单次任务允许的参考图片格式、数量、大小，以及视频输出保存期限。
- 内部访问是否需要最小登录保护，及其部署网络边界。
